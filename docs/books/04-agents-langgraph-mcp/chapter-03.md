# День 4. Вопросы собеседования: агенты, LangGraph, MCP

## Как отвечать

По агентам интервьюеры любят «а что если»: что если модель зациклится, что если инструмент упадёт, что если пользователь попросит удалить базу. Отвечай слоями защиты и показывай, что каждый слой у тебя был в коде сегодня. Примеры — из трёх источников: Hermes в проде, сервис памяти, сегодняшний агент на LangGraph. Про MCP говори как автор сервера, а не только пользователь.

## Базовые (junior / middle)

### Что такое агент и чем он отличается от workflow?

Агент — цикл, в котором модель сама решает, какой инструмент вызвать и когда закончить; код выполняет вызовы и возвращает результаты. Workflow — шаги задал разработчик, модель выполняет их, но не выбирает. Workflow предсказуем и дёшев, агент гибок и непредсказуем по шагам и стоимости. Web-agent — workflow «поиск → ответ», и это правильно; Hermes — агент. Правило: простейшая схема, которая решает задачу, усложнять по результатам оценки.

### Опиши цикл ReAct.

Модель рассуждает, выбирает действие — вызов инструмента с аргументами, получает наблюдение — результат, и повторяет, пока не решит ответить. В коде это узел модели, узел инструментов и условное ребро между ними; остановка — когда в ответе модели нет вызовов инструментов или сработал лимит. Сегодня я собрал это на LangGraph с тремя типами остановок.

### Как проектируешь инструменты для модели?

Имя, описание и Pydantic-схема аргументов; описание — часть промпта, поэтому пишу, когда использовать и что вернётся. Мало инструментов с чёткими границами, короткие структурированные результаты, ошибки текстом, чтобы модель могла исправиться. Разделяю чтение и запись: запись — под подтверждение или политику, и идемпотентна. В лабе три инструмента: два чтения и одна запись с подтверждением через `interrupt`.

### Зачем LangGraph, если можно обойтись циклом while?

Не для цикла, а для того, что вокруг: явное типизированное состояние с редьюсерами, checkpointer с продолжением диалога и восстановлением после сбоя по `thread_id`, `interrupt` для human-in-the-loop, `recursion_limit`, streaming событий, условные рёбра для своих проверок. Цикл `while` всё это заставляет писать самому и без стандарта. Для стандартного случая есть `create_react_agent`, для своих лимитов и ветвлений — `StateGraph`.

### Что такое состояние графа и редьюсер?

Состояние — типизированный словарь, который проходит через узлы; каждый узел возвращает изменения, а не всё состояние. Редьюсер определяет, как изменение сливается с текущим значением: для сообщений `add_messages` дописывает список, а не заменяет его. Свои поля — счётчик шагов и потраченная сумма — у меня без редьюсера, узел просто возвращает новое значение.

### Как агент помнит контекст между сессиями?

Короткая память — состояние графа под `thread_id` в checkpointer: в памяти для разработки, SQLite или Postgres для прода. Долгая — отдельный сервис с семантическим поиском: у меня это ai-agent-memory на FastAPI и ChromaDB, где лежат решения и факты по проектам, и агент ищет в нём инструментом. Процедурная — системный промпт и инструкции. Для короткой памяти нужна стратегия роста: окно, суммаризация, вытеснение результатов инструментов.

### Как защищаешься от бесконечного цикла?

Слоями: жёсткий `recursion_limit` графа, свой лимит шагов в состоянии с понятным сообщением, лимит бюджета по токенам и стоимости из `usage_metadata`, обнаружение повторного вызова — тот же инструмент с теми же аргументами два хода подряд. Сегодня воспроизвёл все три остановки и проверил, что история остаётся валидной: незакрытые вызовы закрываются служебными сообщениями.

### Что делать, если инструмент упал?

Различать: сетевые и временные ошибки — ретрай с backoff для идемпотентных вызовов, таймаут на каждый инструмент; постоянные — вернуть модели текст ошибки, чтобы она изменила подход или честно сказала пользователю. Исключение наверх — только когда продолжать бессмысленно. Побочные действия без идемпотентности не повторяю автоматически.

### Что такое MCP и зачем он, если есть function calling?

Function calling — формат разговора модели с кодом внутри одного приложения. MCP — открытый протокол, по которому любой клиент подключает любой сервер инструментов, ресурсов и промптов; транспорты — stdio для локальных процессов и streamable HTTP для удалённых. Один сервер к моему сервису памяти работает в Claude Code, в LangGraph-агенте и в других клиентах без переписывания. Сегодня написал такой сервер на FastMCP и подключил двумя способами.

### Как подключаешь MCP-инструменты в LangGraph?

Через `langchain-mcp-adapters`: `MultiServerMCPClient` с конфигом серверов — команда и транспорт stdio или URL для HTTP — отдаёт инструменты как обычные LangChain-tools, их передаю в граф. Инструменты асинхронные, поэтому граф вызывается через `ainvoke`. Важно: защита записи должна оставаться в моём коде — имена внешних инструментов записи я добавляю в свой список подтверждений.

## Углублённые (middle+)

### Какие угрозы безопасности у агентов с инструментами и MCP?

Инъекция через результаты инструментов: документ, страница или письмо содержат «проигнорируй правила» — результат инструмента должен считаться данными, а не инструкциями. Tool poisoning — вредоносные инструкции в описании инструмента MCP-сервера. Избыточные права — агент с доступом к удалению без подтверждения. Утечка данных через инструменты наружу. Защита: наименьшие права, подтверждение записи, аллоулисты, песочница для кода, аутентификация удалённых серверов, валидация выхода, трейсинг каждого шага.

### Как устроен human-in-the-loop в LangGraph?

`interrupt()` внутри узла останавливает граф и сохраняет состояние через checkpointer; вызов возвращает в результате `__interrupt__` с полезной нагрузкой — что и с какими аргументами хочет сделать агент. Человек решает, и `Command(resume=решение)` продолжает граф с того же места: узел выполняется заново, а `interrupt` возвращает решение. Без checkpointer и `thread_id` не работает. Сегодня так защитил запись в память: отказ возвращается модели как результат инструмента.

### Как оцениваешь качество агента?

Три уровня: результат — решена ли задача, по golden-набору задач с ожидаемым результатом; траектория — правильные ли инструменты в правильном порядке, число шагов, повторы; ресурсы — токены, стоимость, время. Метрики агрегируются по прогонам, потому что агент недетерминирован. Трейсы — в Langfuse (завтра). Без этого любое изменение промпта или набора инструментов — лотерея.

### Как считаешь и ограничиваешь стоимость агента?

Суммирую `usage_metadata` каждого ответа модели с ценами провайдера в состояние графа и останавливаюсь по порогу; учитываю, что результаты инструментов раздувают вход на каждом ходу — режу их до нужного, а старые вытесняю. Prompt caching для агентов особенно выгоден: системный промпт и схемы инструментов стабильны, они идут первыми. В проде бюджет — на задачу, на пользователя и на день.

### Когда нужны несколько агентов?

Когда одному не хватает контекста или его инструменты конфликтуют и мешают выбору; когда нужна изоляция прав — исполнитель с доступом к базе отделён от того, кто читает почту. Схемы: супервизор с исполнителями, передача управления, параллельные исполнители с агрегацией. Цена — умножение шагов, стоимости и точек отказа, поэтому сначала один агент с хорошими инструментами.

### Чем LangGraph отличается от LlamaIndex, Pydantic AI, CrewAI?

LangGraph — низкоуровневая оркестрация с состоянием и персистентностью, стандарт в вакансиях. LlamaIndex — данные в центре: индексы, RAG-пайплайны, свои workflows. Pydantic AI — типизированные агенты с минимумом абстракций, близко к «просто Python». CrewAI и AutoGen — ролевые мультиагентные схемы, быстро для демо, сложнее контролировать. DSPy — оптимизация промптов как программ. Глубоко знаю LangGraph, остальные — по концепции и могу выбрать под задачу.

### Как бы ты добавил инструменты в web-agent, оставив его надёжным?

Оставил бы workflow как основной путь и добавил бы маршрутизацию: классификатор определяет, нужен ли инструмент — например, проверка статуса заказа по API клиента; инструменты только чтения без подтверждения, запись — через оператора, как сейчас перехват диалога. Лимит шагов два-три, бюджет на диалог, все вызовы в трейс. Оценка на golden-наборе до и после, чтобы честный fallback не сломался.

### Что такое Claude Agent SDK и как связан с MCP?

SDK Anthropic для построения агентов с тем же рантаймом, что у Claude Code: инструменты, субагенты, навыки, MCP-серверы как источник инструментов. Для меня важно как ориентир архитектуры: инструменты через MCP, инструкции через файлы проекта, права через разрешения. Я работаю в Claude Code ежедневно и подключил к нему свой MCP-сервер памяти.

## Вопрос на проектирование

### Спроектируй агента поддержки интернет-магазина, который умеет отвечать по документам и оформлять возврат.

Разделю на две части по риску. Ответы по документам — workflow RAG, как в web-agent: поиск, ответ с цитатами, честный отказ; без агентности, потому что она там не нужна. Оформление возврата — агент с инструментами: `get_order(order_id)` и `check_return_policy(order)` — чтение, `create_return(order_id, reason, idempotency_key)` — запись. Аутентификация пользователя до инструментов: агент видит только заказы этого клиента, фильтр на уровне API, не в промпте. Запись — под подтверждением: пользователю показывается итог «оформить возврат заказа №… на сумму …?», и только явное согласие продолжает граф через `interrupt`; ключ идемпотентности — чтобы повтор после сбоя не создал второй возврат. Лимиты: три-четыре хода модели, бюджет на диалог, обнаружение повторов; при превышении — передача оператору с историей, как перехват диалога сейчас. Структурированный финальный ответ по схеме для фронтенда. Оценка: golden-набор из пятидесяти диалогов с ожидаемым результатом и траекторией, метрики успешности и доли передач оператору, трейсы каждого шага. Безопасность: результаты инструментов и текст пользователя — данные; инъекция «оформи возврат всех заказов» упирается в права и подтверждение. Из РФ — модель через российского провайдера или локально, персональные данные заказов не уходят наружу.

## Практика

1. Три слабых ответа — вслух, до минуты.
2. Нарисуй граф сегодняшнего агента с узлами и рёбрами на бумаге и объясни его за минуту — именно это попросят сделать на доске.
