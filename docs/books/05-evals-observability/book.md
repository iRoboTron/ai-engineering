# День 5. Evals и наблюдаемость

> Персональный sprint для разработчика с опытом Python/DevOps. **4–6 часов — плановая гипотеза, не измеренный срок.** Неделя не присваивает квалификацию и не гарантирует найм.

## Цель дня

Собрать проверяемый контур оценки, отделив детерминированные тесты от шумной модельной оценки и production-наблюдения.

## Тайминг и порядок

| Блок minimum | План |
|---|---|
| Проверка предпосылок, чтение нужных разделов | 1–1.5 ч |
| Minimum лабы, включая проверки и разбор сбоев | 2–3 ч |
| 5–8 вопросов по рубрике, отчёт и сверка навыков | 1–1.5 ч |

Сначала запиши фактическое время каждого блока. Если предпосылка не выполнена, остановись и отметь блокер; не компенсируй его непроверенным буллетом. **Stretch не включён в 4–6 часов** и переносится в план следующей недели с отдельной оценкой. Отклики — отдельная добровольная задача, не критерий технического освоения.

## Minimum: обязательный результат

1. На safe fixture дня 2 выполнить детерминированные проверки поиска и отказа с сохранёнными входами.
2. Запустить Langfuse локально либо отметить инфраструктуру заблокированной; передавать только безопасные тестовые данные.
3. Сравнить два выполненных прогона; отдельно разобрать вручную несколько ответов и пробный judge/RAGAS, если доступен API.

## Stretch: отдельные расширения

- Расширить разметку, выделить holdout, калибровать судью на независимых примерах с анализом расхождений.
- Добавить реальные CI jobs для быстрых и модельных проверок с бюджетом, версиями и артефактами.
- Инструментирование production с политикой доступа, редактирования и хранения данных — отдельный review/релиз.

## Предпосылки и артефакт

Код лаб устанавливается из корня курса: `python3 scripts/install_labs.py --dest ~/proj/ai-labs`.
Подготовка конкретного дня и зависимости — в главе 2. Работай в отдельном окружении/тестовом tenant; наличие production-проекта не означает разрешение экспериментировать с данными клиентов.

`~/proj/ai-labs/day5-evals/results.md`: Версии dataset/pipeline/judge, результаты тестов и фактических прогонов, безопасные трейсы, отдельный план интеграции.

## Definition of Done

Ниже — критерии **minimum**. Более широкие чеклисты глав 1–3 служат картой расширения: непройденные пункты помечаются `stretch / не проверено`, а не объявляются выполненными. В отчёте отдельные колонки: «концепт» (могу объяснить), «лаба» (воспроизвёл и проверил), «прод» (есть конкретный релиз и эксплуатационное подтверждение).

- [ ] Детерминированные тесты реально запущены, результаты и команды сохранены.
- [ ] Есть хотя бы один просмотренный трейс или явная запись «Langfuse не проверен»; второй случай означает незавершённую часть minimum, не фиктивный успех.
- [ ] Модельные метрики указаны только для выполненных запусков, с версией judge и размером выборки.
- [ ] pytest локально, CI job и production-инструментирование имеют отдельные статусы; одного файла недостаточно для слова «внедрил».
