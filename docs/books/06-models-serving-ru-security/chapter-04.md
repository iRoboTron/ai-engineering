## Формулировки для резюме

- Провёл **red team собственной RAG-платформы** по OWASP Top 10 for LLM Applications 2025: набор из десяти атак (прямые и непрямые инъекции, утечка системного промпта, эксфильтрация через markdown, XSS в ответах, межтенантный доступ, исчерпание ресурсов) с автоматическими проверками; закрыл найденное: разделение данных и инструкций, канарейка, фильтрация выхода, бюджет сессии.
- Рассчитываю и измеряю **ресурсы инференса**: калькулятор памяти GPU (веса и KV-cache под контекст и параллелизм), замеры Ollama для квантизаций Q4 и Q8, сравнение с расчётом; понимаю, когда vLLM, а когда Ollama или llama.cpp.
- Ориентируюсь в **российском контексте**: OpenAI-совместимый доступ к YandexGPT, GigaChat, открытые модели для русского (Qwen, T-Pro и другие), лицензии, 152-ФЗ и схема потоков данных, эксплуатация зарубежных API в условиях геоблокировки.
- Объясняю дерево решений **промпт → RAG → дообучение** и LoRA/QLoRA концептуально; оцениваю окупаемость собственного инференса против API по прайсу и объёму.
- Security-фундамент: авторские практические книги по периметру, веб-безопасности, сетевой защите, реагированию на инциденты, Vault и Linux hardening — применяю к LLM-системам.

Ключевые слова: OWASP LLM Top 10, prompt injection, red teaming, vLLM, Ollama, llama.cpp, квантизация, GGUF, AWQ, KV-cache, LoRA, YandexGPT, GigaChat, 152-ФЗ, on-prem LLM.

«По OWASP Top 10 for LLM 2025 — и не по списку, а по результатам атак на свой продукт. Собрал десять атак: прямые и непрямые инъекции, утечку системного промпта, эксфильтрацию через markdown-картинки, XSS в ответе, попытку добраться до чужого tenant, исчерпание ресурсов. Прогнал против тестового tenant с отравленным документом. Часть защит уже была: изоляция коллекций, rate limit, лимит длины, капча, честный отказ, отсутствие инструментов у модели. Провалилась непрямая инъекция через документ и фильтрация выхода — закрыл разделением данных и инструкций, канарейкой с детекцией, фильтром ссылок и картинок, бюджетом на сессию; набор атак теперь прогоняется при каждом изменении промпта. Что не закрывается полностью — непрямая инъекция; снижаю вероятность и последствия и говорю об этом заказчику прямо. Плюс инфраструктурная часть: safetensors, фиксированные образы, маскирование ПДн в трейсах, российский провайдер или on-prem для персональных данных».
