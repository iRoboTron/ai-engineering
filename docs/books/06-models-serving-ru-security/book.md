# День 6. Инференс и безопасность LLM-систем

> Персональный sprint для разработчика с опытом Python/DevOps. **4–6 часов — плановая гипотеза, не измеренный срок.** Неделя не присваивает квалификацию и не гарантирует найм.

## Цель дня

Измерить один доступный сценарий инференса и проверить несколько защит в изолированном стенде; не выдавать это за сертификацию безопасности.

## Тайминг и порядок

| Блок minimum | План |
|---|---|
| Проверка предпосылок, чтение нужных разделов | 1–1.5 ч |
| Minimum лабы, включая проверки и разбор сбоев | 2–3 ч |
| 5–8 вопросов по рубрике, отчёт и сверка навыков | 1–1.5 ч |

Сначала запиши фактическое время каждого блока. Если предпосылка не выполнена, остановись и отметь блокер; не компенсируй его непроверенным буллетом. **Stretch не включён в 4–6 часов** и переносится в план следующей недели с отдельной оценкой. Отклики — отдельная добровольная задача, не критерий технического освоения.

## Minimum: обязательный результат

1. Рассчитать память модели и KV-cache с явными допущениями; измерить одну доступную Ollama-конфигурацию.
2. Прогнать безопасный набор атак в отдельном тестовом tenant/стенде, сохранив ожидаемые и наблюдаемые исходы.
3. Для одного найденного дефекта предложить/проверить исправление и регрессионный тест; если дефект не найден, добавить новый тест без выдуманного успеха.

## Stretch: отдельные расширения

- Сравнить Q4/Q8 при одинаковых настройках и нагрузке; vLLM — самостоятельный запуск с нагрузочным профилем.
- Вызвать российского провайдера, если есть аккаунт и допустимые тестовые данные; без аккаунта — только план.
- Расширить red-team набор до десяти категориальных сценариев и ручного review; production-изменения — отдельно.

## Предпосылки и артефакт

Код лаб устанавливается из корня курса: `python3 scripts/install_labs.py --dest ~/proj/ai-labs`.
Подготовка конкретного дня и зависимости — в главе 2. Работай в отдельном окружении/тестовом tenant; наличие production-проекта не означает разрешение экспериментировать с данными клиентов.

`~/proj/ai-labs/day6-serving-security/results.md`: Замеры доступной конфигурации, список атак, результаты ручного review и regression tests; нет обязательного взлома/исправления прода.

## Definition of Done

Ниже — критерии **minimum**. Более широкие чеклисты глав 1–3 служат картой расширения: непройденные пункты помечаются `stretch / не проверено`, а не объявляются выполненными. В отчёте отдельные колонки: «концепт» (могу объяснить), «лаба» (воспроизвёл и проверил), «прод» (есть конкретный релиз и эксплуатационное подтверждение).

- [ ] Отчёт содержит допущения расчёта и измерения; GPU, квантование, контекст и параллелизм зафиксированы.
- [ ] Атаки выполнялись только в разрешённом тестовом контуре; сохранены входы, исходы и ручной разбор.
- [ ] «PASS» отдельной атаки не объявляется доказательством отсутствия уязвимости; неизвестное не считается защищённым.
- [ ] Ollama, vLLM и RU API имеют независимые статусы «концепт / лаба / прод»; отсутствие аккаунта/железа отмечено.
