---

## 🚦 Главное правило

Книга сделана, только когда валидатор печатает `PASS`:

```bash
cd docs/books
python3 validate-book.py 0N-slug              # вся книга
python3 validate-book.py 0N-slug chapter-02.md # одна глава
```

Без `PASS` книгу не регистрируем в `files.json` и не деплоим.

## Кто читатель

Читатель — автор серии. Он **не новичок**: программист с DevOps-фундаментом (Linux, Docker, nginx,
PostgreSQL, CI/CD, мониторинг), у которого в проде уже работают:

- `~/proj/web-agent` — multi-tenant RAG-платформа: FastAPI, ChromaDB (коллекция на tenant), PostgreSQL + Alembic,
  `RecursiveCharacterTextSplitter` (500/50), эмбеддинги `text-embedding-3-small` через OpenRouter,
  Telegram-бот, виджет, админка с RBAC, честный fallback со сбором лидов, CI/CD (Ansible rolling update, self-test-гейт).
  Прод: agent1.adelfos.ru, ksm.adelfos.ru. Код RAG: `services/agent-api/app/rag/{retriever,embeddings,chain}.py`,
  индексация: `services/doc-parser/app/indexer.py`.
- `~/proj/ai-agent-memory` — сервис памяти агентов: FastAPI + ChromaDB + `all-MiniLM-L6-v2` + PostgreSQL (LXC 115, `http://100.69.146.20:443`).
- Hermes Agent в Telegram (LXC 103): systemd, OpenRouter, прокси через socks5 при геоблоке.
- Ollama и Open-WebUI (книга 23 курса devops), ComfyUI с API на ПК с RTX 3070 Ti.
- Homelab: Proxmox `pxhome`, LXC-контейнеры, nginx на LXC 109, NPM на LXC 101.

Поэтому: **не объяснять Docker, Postgres, HTTP, Python.** Объяснять то, что относится к LLM/RAG/агентам,
и всегда связывать с тем, что у читателя уже есть («в web-agent это делается так-то, а индустрия называет это …»).

Цель читателя — **пройти собеседование на AI/LLM-инженера в РФ** и начать откликаться со дня 2.
Каждая глава отвечает на вопрос «как это поможет на собеседовании или в портфолио».

## Формат книги-дня (одинаков для книг 01–06; книга 07 — см. её ТЗ)

```
0N-slug/
├── book.md          ← цель дня, тайминг по часам, оглавление, что будет в конце дня
├── chapter-01.md    ← Суть      (конспект, 1–1.5 ч чтения, 6–10 страниц)
├── chapter-02.md    ← Лаба      (пошагово, 2–3 ч, в СВОИХ проектах)
├── chapter-03.md    ← Вопросы собеседования (15–20 вопросов с ответами, 0.5–1 ч)
├── chapter-04.md    ← Что показать работодателю (артефакт дня, формулировки для резюме, 1–2 стр)
└── glossary.md      ← ≥ 6 терминов, формат «**Термин (English)** — объяснение»
```

Объём книги — **15–30 страниц**. Больше — значит, книга не будет прочитана за день. Режь.

Нумерация книг **01–07** (не 00): ридер парсит `b` через `parseInt`.

## Требования к содержанию

- **Язык:** русский, на «ты», термины с английским оригиналом при первом упоминании: «реранкинг (reranking)».
- **Никакой воды.** Без «в наше время ИИ развивается стремительно». Каждый абзац — либо факт, либо решение, либо пример.
- **Факты сверять**, не брать из памяти модели: версии библиотек, имена моделей, эндпоинты провайдеров
  (YandexGPT, GigaChat, OpenRouter), API RAGAS/Langfuse/LangGraph. Использовать context7 или веб на момент написания.
  Если сверить нельзя — писать «на момент написания (сентябрь 2026)» и давать команду, которой читатель проверит сам.
- **Код только в блоках с языком** (```python, ```bash, ```yaml, ```sql, ```json). Код рабочий, без `...` в середине.
- **Лаба — в своих проектах.** Пути реальные: `~/proj/web-agent/...`, `~/proj/ai-agent-memory/...`.
  Самостоятельные скрипты лаб — в публичном репозитории портфолио `~/proj/ai-labs/dayN-…/`; правки web-agent и ai-agent-memory — в их собственных репозиториях. Так каждый артефакт виден работодателю.
- **Не дублировать** книгу 23 devops (Ollama/Open-WebUI/nginx) и лекции Anthropic по MCP — ссылаться.
- **Диаграммы Mermaid** — минимум 2 на книгу, у каждого узла `style … fill:#…,color:#fff` из палитры
  (`#2d2d2d` вход, `#1a5276` шаг, `#1e8449` успех, `#6e2f1a` ошибка, `#7d6608` данные, `#4a235a` внешнее).
- **Честность про рынок:** где требования вакансий расходятся с реальной практикой — говорить прямо.

`foo/bar/baz/lorem/TODO/FIXME/«здесь будет»/НАПИСАТЬ`, тег `<placeholder`, незаполненные `<<`,
иероглифы/кана, дубли код-блоков, два блока файлового дерева в одном файле, глава без `## Что проверить`,
глава без первой строки `# …`, диаграмма без `style … fill`.

## Порядок работы

1. Прочитать этот файл, `AUTHORING-CONVENTIONS.md`, `README.md` (карта недели) и ТЗ книги `AGENT-INSTRUCTIONS-book-0N.md`, если есть.
2. `book.md` → `chapter-01.md` → `chapter-02.md` → `chapter-03.md` → `chapter-04.md` → `glossary.md`.
   После каждой главы: `python3 validate-book.py 0N-slug chapter-0K.md`.
3. Полная проверка `python3 validate-book.py 0N-slug` → `PASS`.
4. Зарегистрировать книгу в `files.json` (массив `{file,title}` в `courses["0N-slug"]`, глоссарий — последним).
5. Добавить `COURSE_META["0N-slug"]` в `index.html`, `COURSE_NAMES["0N-slug"]` в `reader.html`, бампнуть `ASSET_VERSION` в обоих.
6. Один коммит на книгу: `Book 0N (Title): initial`. Правки — `Book 0N (Title) chK: <что сделано>`.
7. Деплой `./deploy-pxhome.sh` из корня проекта; проверить `curl -I https://ai-engineering.adelfos.ru/files.json` → 200.
