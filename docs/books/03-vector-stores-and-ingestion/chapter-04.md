# День 3. Что показать работодателю

## Артефакт дня

`~/proj/ai-labs/day3-pgvector/` — воспроизводимый стенд: Docker Compose с pgvector, схема с HNSW, полнотекстом и RLS, загрузка векторов, гибридный запрос одним SQL, оценка на том же golden-наборе и `results.md` со сравнением Chroma и pgvector, планами EXPLAIN и доказательством изоляции tenant. Отдельная ценность — **план миграции web-agent** из пяти шагов с оценкой часов и рисками: он показывает, что ты мыслишь как инженер, который меняет прод без простоя, а не как автор ноутбука.

## Формулировки для резюме

- Провёл сравнение векторных хранилищ для RAG-платформы: ChromaDB против PostgreSQL с pgvector на одном golden-наборе — качество (recall@k, MRR), латентность, планы запросов с HNSW, поведение фильтров с итеративным сканом pgvector 0.8.
- Реализовал **гибридный поиск в одном SQL-запросе**: pgvector (HNSW, косинус) + полнотекстовый поиск PostgreSQL с русской морфологией, слияние через Reciprocal Rank Fusion.
- Спроектировал и продемонстрировал **изоляцию tenant через row-level security** в PostgreSQL: политика по `tenant_id`, защита от забытого фильтра, проверка утечки.
- Составил план миграции продовой multi-tenant RAG-платформы с ChromaDB на pgvector без простоя: двойная запись, backfill, переключение по метрикам, риски пула соединений и сборки индекса.
- Проектирую пайплайн индексации как ETL: инкрементальная переиндексация по хэшу, идемпотентный upsert по детерминированным id, дедупликация, DLQ, контроль расхождения источник–метаданные–индекс; выбор парсеров PDF (pypdf, Docling, OCR) по типу документов.

Ключевые слова: pgvector, HNSW, IVFFlat, PostgreSQL, tsvector, row-level security, Qdrant, ChromaDB, Docling, ingestion pipeline, идемпотентность, multi-tenancy.

## Как рассказать за 2 минуты

На вопрос «как у вас устроено хранение и что будет при росте»:

«Сейчас в проде ChromaDB с коллекцией на tenant — простое и безопасное решение для старта: утечка между клиентами невозможна без ошибки в имени коллекции. Границы Chroma известны: один узел, индекс в памяти, нет полнотекста и транзакций с остальными данными, а метаданные документов у меня в Postgres — после инцидента, когда миграция перенесла метаданные, но не векторы, я хочу одну правду о данных. Поэтому я собрал стенд на pgvector: те же чанки и векторы, HNSW, полнотекст с русской морфологией и гибрид через RRF в одном SQL, изоляция через RLS — забытый WHERE больше не утечка. На golden-наборе dense совпал с Chroma, гибрид добавил …, латентность … мс. План миграции — двойная запись, backfill, переключение по метрикам, … часов. При росте до десятков миллионов чанков и сложных фильтров смотрел бы на Qdrant с tenant-индексом — но не раньше, чем упрусь в Postgres».
