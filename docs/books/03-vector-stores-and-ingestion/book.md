# День 3. Векторные хранилища и пайплайн индексации

> Книга 3 из 7 серии «ИИ-инженер: практический трек за неделю». Один день, 4–6 часов. Твой самый сильный день: это DevOps-территория.

---

## Цель дня

К вечеру ты:

- объясняешь, как устроены HNSW и IVFFlat, что значат `m`, `ef_construction`, `ef_search`, `lists`, `probes`, и почему индекс — это торг между recall и латентностью;
- выбираешь хранилище под задачу — Chroma, pgvector, Qdrant, Milvus, Elasticsearch — по критериям, а не по моде, и знаешь границы каждого;
- держишь векторы в PostgreSQL рядом с обычными данными: pgvector с HNSW, полнотекстовый поиск и гибрид в одном SQL, изоляция tenant через row-level security;
- описываешь пайплайн индексации как инженерную систему: парсинг PDF с таблицами, инкрементальная переиндексация по хэшу, дедупликация, удаление и метрики;
- имеешь план миграции web-agent с Chroma на pgvector с оценкой трудозатрат.
