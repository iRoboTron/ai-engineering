# День 3. Векторные хранилища и индексация

> Персональный sprint для разработчика с опытом Python/DevOps. **4–6 часов — плановая гипотеза, не измеренный срок.** Неделя не присваивает квалификацию и не гарантирует найм.

## Цель дня

Проверить pgvector на том же наборе данных и продемонстрировать изоляцию; решение о миграции принять по критериям.

## Тайминг и порядок

| Блок minimum | План |
|---|---|
| Проверка предпосылок, чтение нужных разделов | 1–1.5 ч |
| Minimum лабы, включая проверки и разбор сбоев | 2–3 ч |
| 5–8 вопросов по рубрике, отчёт и сверка навыков | 1–1.5 ч |

Сначала запиши фактическое время каждого блока. Если предпосылка не выполнена, остановись и отметь блокер; не компенсируй его непроверенным буллетом. **Stretch не включён в 4–6 часов** и переносится в план следующей недели с отдельной оценкой. Отклики — отдельная добровольная задача, не критерий технического освоения.

## Minimum: обязательный результат

1. Поднять отдельный учебный PostgreSQL с pgvector, загрузить тот же tenant/snapshot и векторы дня 2.
2. Сравнить dense Chroma/pgvector с одинаковыми k, метрикой и разметкой; выполнить EXPLAIN и негативные тесты RLS.
3. Составить решение: оставить текущую систему или исследовать миграцию; указать ограничения небольшого fixture.

## Stretch: отдельные расширения

- Проверить hybrid SQL, ANN на достаточном объёме, фильтры и recall относительно точного поиска.
- Docling/Qdrant, инкрементальная индексация, restore drill и миграционный rehearsal — отдельные опыты.
- План миграции с dual write/backfill/rollback нужен только при обоснованном выборе миграции.

## Предпосылки и артефакт

Код лаб устанавливается из корня курса: `python3 scripts/install_labs.py --dest ~/proj/ai-labs`.
Подготовка конкретного дня и зависимости — в главе 2. Работай в отдельном окружении/тестовом tenant; наличие production-проекта не означает разрешение экспериментировать с данными клиентов.

`~/proj/ai-labs/day3-pgvector/results.md`: Compose, SQL/загрузчик, snapshot, планы запросов, результаты RLS и решение, включая вариант «не мигрировать».

## Definition of Done

Ниже — критерии **minimum**. Более широкие чеклисты глав 1–3 служат картой расширения: непройденные пункты помечаются `stretch / не проверено`, а не объявляются выполненными. В отчёте отдельные колонки: «концепт» (могу объяснить), «лаба» (воспроизвёл и проверил), «прод» (есть конкретный релиз и эксплуатационное подтверждение).

- [ ] Сравниваются одинаковые tenant/snapshot, embedding-модель и размерность; результаты — Hit@k и MRR@5.
- [ ] Записаны роль подключения, четыре сценария RLS и фактически видимые строки; admin не используется как приложение.
- [ ] EXPLAIN сохранён; если маленький набор даёт Seq Scan, это объяснено, а не скрыто.
- [ ] Есть решение с критерием пересмотра; перенос в production не считается выполненным по учебному SQL.
