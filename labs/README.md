# Исполняемые лабораторные

Это проверяемые исходники учебных примеров, **не набор уже выполненных достижений**.
Начни с `day1-llm-basics`, затем читай соответствующую главу курса. Файлы `dayN-*`
генерируются из именованных блоков Markdown скриптом `scripts/sync_labs.py` в репозитории
курса; редактировать личную установленную копию для экспериментов нормально.

## Окружение

CPython 3.12, Linux x86-64/glibc ≥2.28. CPU wheel PyTorch указан прямой ссылкой;
CUDA-зависимости не устанавливаются. Установщик примеров ничего не запускает.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.txt
python -m pip check
```

В `requirements.txt` зафиксированы также транзитивные зависимости и SHA256.
Langfuse закреплён на учебной линии SDK3; это выбор воспроизводимости существующего API,
не рекомендация использовать старую ветку в проде. Изменение версии требует повторной
проверки примеров, self-hosted server и API. Не устанавливай поверх произвольные latest.

Обновление lockfile делается **в репозитории курса**, после проверки API и тестов:

```bash
uv pip compile labs/requirements.in --python-version 3.12 --python-platform x86_64-unknown-linux-gnu --emit-index-url --generate-hashes -o labs/requirements.txt
```

## Данные и публикация

- `fixtures/corpus/` и `fixtures/golden.jsonl` — вымышленные публичные учебные данные.
  Малый набор служит smoke/demo, а не доказательством качества на клиентах.
- Реальные документы/чаты и их производные индексы храни вне публичного Git.
- `.local/`, `.env`, Chroma, сырые JSON-ответы и результаты red-team не публикуются.
- `.gitignore` не удаляет уже отслеживаемые файлы! Перед первым push проверь
  `git ls-files` и `git diff --cached`; при обнаружении секрета прекрати публикацию,
  отзови ключ и очисти историю по принятой политике.
- Не используй `git add -A` без проверки. Публикуй явно выбранные скрипты и обезличенные
  агрегированные результаты, а не сырые клиентские данные или трейсы.

## Доказательства

Отдельно записывай: offline unit tests, локальную интеграцию, модельный/API прогон,
эксплуатацию в проде. `SKIP` или `ERROR` — не `PASS`. Фиксируй версии, snapshot корпуса,
фильтры, цены, cold start отдельно от warm latency, Hit@k и ручные промахи.
Для budget guard нужна ещё квота провайдера: локальная оценка не является жёстким
ограничением списания. Для реальных атак используй только собственный тестовый tenant.
