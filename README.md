# ИИ-инженер: практический трек подготовки

Семь книг-дней для **разработчика с Python/DevOps-базой и опытом приложений**, который
хочет систематизировать LLM/RAG, собрать проверяемый кейс и подготовиться к собеседованию.
Это персональный интенсив, **не обучение профессии с нуля, не подтверждение уровня middle
и не гарантия найма за неделю**.

Сайт: https://ai-engineering.adelfos.ru · [Правила авторства](AUTHORING-CONVENTIONS.md)

## Программа и границы

| День | Обязательное направление | Проверяемый результат |
|---|---|---|
| 1 | LLM API, structured outputs, streaming, стоимость и retry | Скрипты, измерения, черновик резюме |
| 2 | Retrieval: dense/BM25/hybrid; корректные метрики | Safe fixture, Hit@k/MRR@5, разбор промахов |
| 3 | pgvector, фильтрация, роли и RLS | Сопоставимый tenant benchmark и отрицательные тесты изоляции |
| 4 | LangGraph, состояние, read/write tools, HITL | Воспроизводимый диалог, подтверждение записи, остановки |
| 5 | Датасет, tracing без секретов, evaluation | Результаты в фиксированном каталоге, калибровка, гейты |
| 6 | Serving и проверка безопасности | Замеры доступного инференса; PASS/FAIL/ERROR для атак |
| 7 | Кейс, вопросы, самостоятельная диагностика | Резюме с доказательствами, mock по рубрике, план пробелов |

Плановые **4–6 часов в день — гипотеза, а не измеренный срок**. Установка окружения,
загрузка моделей, регистрация провайдеров и устранение внешних сбоев учитываются отдельно.
В каждой книге разделены обязательный минимум и расширения. Реранкинг/сравнение эмбеддингов,
MCP, российский API, RAGAS или локальный serving выполняются согласно выбранной ветке;
пропущенное расширение не становится навыком в резюме.

Фиксируй уровень каждого навыка: **концепт / выполненная лабораторная / эксплуатация в проде**.
Курс использует `web-agent` и `ai-agent-memory` как контекст, но по умолчанию работает на
вымышленных учебных данных. Изменения реальных проектов — только в их ветках с собственной
проверкой. Продовые документы, ключи и пользовательские чаты не нужны для базового маршрута.

## Быстрый старт

Локальная читалка (зависимости ридера включены в репозиторий):

```bash
cd /home/adelfos/Documents/lessons/ai-engineering
python3 -m http.server 8080 --bind 127.0.0.1 --directory docs/books
```

Открой http://127.0.0.1:8080/ . Готовые примеры находятся в `labs/`.
Установщик **не перезаписывает** отличающиеся существующие файлы: при конфликте ничего
не копируется, следует выбрать новую папку или вручную объединить изменения.

```bash
python3 scripts/install_labs.py --dest ~/proj/ai-labs
cd ~/proj/ai-labs
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.txt
```

Lockfile рассчитан на **CPython 3.12, Linux x86-64 (glibc ≥ 2.28), CPU PyTorch**.
Загрузка зависимостей может быть большой; GPU, Windows и другие Python требуют отдельно
проверенного окружения. Инсталляция сама не вызывает модели и не запускает Docker.
Ключи задаются локально; секреты и вычисленные артефакты исключены из Git.
Подробнее: [инструкция к лабораторным](labs/README.md).

## Что означает «проверено»

`validate-book.py` проверяет структуру, синтаксис и ссылки. Его `PASS` **не доказывает**
работоспособность лабораторной, безопасность решения или юридическое соответствие.

```bash
# После изменения именованных примеров/вопросов:
python3 scripts/sync_labs.py
python3 scripts/build_question_bank.py

# Без сети, ключей, Docker, GPU и сторонних Python-пакетов:
python3 scripts/check_project.py

# Реальный браузер: локальные страницы, без внешних CDN
npm ci
npx playwright install chromium
npm run test:reader
```

Если Chrome уже установлен: `CHROME_PATH=/usr/bin/google-chrome npm run test:reader`.
CI выполняет offline gate и браузерные тесты. Платные API, реальная генерация, загрузка
моделей и защищённость стороннего приложения **не подменяются моками**: они требуют
отдельного прогона и отчёта с версиями, датой, входными данными и ограничениями.
Список исправлений и границы проверки: [AUDIT-FIXES.md](AUDIT-FIXES.md).

## Как устроен проект

- `docs/books/` — семь книг, манифест, ридер и локальные библиотеки `vendor/`.
- `labs/` — экспортированные исполняемые примеры, безопасный fixture и lockfile.
- `scripts/sync_labs.py` — проверяемая синхронизация именованных блоков книг с кодом.
- `scripts/build_question_bank.py` — банк вопросов с содержательными рубриками.
- `tests/` — регрессионные проверки и тесты ридера.
- `scripts/build_site.py` — публикация только файлов из белого списка, включая `labs.zip`.
- `deploy-pxhome.sh` — изолированные staging/release, rollback, HTTP self-check и HTTPS.
- `career/` — личные заготовки, исключены из Git и публикации.

## Публикация

Проверка сборки без доступа к серверу:

```bash
BUILD_DIR=/tmp/ai-engineering-site-review ./deploy-pxhome.sh --build-only
```

`BUILD_DIR` должен быть новым путём. Публикация по отдельному решению: `./deploy-pxhome.sh`.
DNS/NPM/TLS настраиваются отдельно; наличие wildcard DNS не доказывает настройку proxy host.
Скрипт не удаляет предыдущий выпуск и восстанавливает его при ошибке локальных проверок
на сервере. Публичный HTTPS проверяется отдельно после переключения.
